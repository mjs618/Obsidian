# Obsidian 库内杂项清理设计

## 背景

当前知识库结构已经稳定，但根目录和 `99-归档/空白占位` 仍保留少量低价值文件：

- 两个内容完全相同的空白 Obsidian Base。
- 两个已经被 `.gitignore` 覆盖、但仍由 Git 跟踪的 AI 日报网页快照。
- 三个已经执行过、包含强制移动或删除命令的旧整理脚本。
- 五个只剩来源说明的空白日记或工具残留。

这些文件不参与当前导航或知识工作流。继续保留会增加根目录噪音，并让旧脚本存在误运行风险。

## 目标与成功标准

1. 从当前知识库删除已确认的 12 个低价值文件。
2. 所有删除都可通过 Git 历史恢复，不清理或改写 Git 历史。
3. 清理后不留下指向已删除文件的有效 wikilink 或维护任务。
4. HTML 快照继续受现有忽略规则保护，避免再次进入 Git。
5. 不触碰本轮范围外的未提交改动。

1. 确认 12 个目标文件均已从工作树删除。
2. 搜索目标文件名，确认现行索引、任务和维护模板中没有残留的有效引用。
3. 确认两个 HTML 文件仍匹配 `.gitignore` 中的 `.codex_hex_*.html`。

5. 运行 Git 差异检查，确认变更仅包含目标删除和直接相关的留痕更新。
