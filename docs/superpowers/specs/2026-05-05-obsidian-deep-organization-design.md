# Obsidian 深度整理设计说明

## 目标

本次整理采用“双层体系收敛”方案：把 `HUB / PARA / ZETA / DAILY / SYSTEM` 定为工作流层，把 `00-99` 编号目录定为内容库层。整理后的知识库应只有一个日常入口、一个全库地图、一套标签与属性规则，以及一条从收集到沉淀的稳定路径。

整理完成后，用户应能从 [[HUB/Home]] 开始日常使用，从 [[HUB/Map]] 理解全库结构，从 `00-管理` 查看治理规则，从编号目录检索长期内容。

## 当前问题

当前库已经有较完整的目录和治理基础，但存在四类结构性问题：

- 入口重叠：`README.md`、[[首页]]、[[HUB/Home]]、[[00-管理/知识库工作台]] 都承担了入口职责。
- 体系并存：Dusk 风格的 `HUB / PARA / ZETA / DAILY` 与原编号目录同时存在，但职责边界还需要更清楚。
- 内容成熟度混合：临时记录、剪藏、正式笔记、项目资料、历史整理文档都能被找到，但“收集、分拣、整理、沉淀、复用”的阶段标识不够稳定。
- 质量债务零散：根目录有空白日记文件；部分长文需要提炼；少量双链、附件链接和短名链接需要修正；历史整理文档需要统一降频或归档。

## 选定方案

采用方案 B：双层体系收敛。

不做彻底重建目录，也不只做表面清理。保留当前编号目录作为内容库，收敛 Dusk 模块作为工作流与导航层。允许移动和重命名文件，但只在职责明显错误、历史文档降频、空白内容清理或链接修复需要时执行。

## 目标结构

### 工作流层

| 模块 | 职责 | 处理原则 |
| --- | --- | --- |
| `HUB` | 日常入口、地图、收件箱、页面任务 | [[HUB/Home]] 是唯一日常入口，[[HUB/Map]] 是唯一全库地图 |
| `PARA` | 项目、领域、资源、归档的行动视角 | 主要链接到编号目录，不重复存放大量正文 |
| `ZETA` | 临时笔记、文献笔记、永久笔记的沉淀视角 | 用于解释知识加工流程，主题正文仍可留在编号目录 |
| `DAILY` | 日、周、月周期复盘入口 | 与模板和工作周报保持链接 |
| `STICKY` | 临时脑暴和短期草稿 | 只放短期内容入口，不承担长期归档 |
| `SYSTEM` | 模板、插件、治理、配置的系统视角 | 链接 `00-管理` 与 `Templates`，不替代治理正文 |

## 文档职责调整

- `README.md`：只保留仓库说明、主入口链接、基本使用方式，不承担日常操作面板。
- [[首页]]：保留为中文轻量入口或转向页，避免和 [[HUB/Home]] 内容重复。
- [[HUB/Home]]：作为唯一日常入口，展示捕获、项目、任务、沉淀和最近更新。
- [[HUB/Map]]：作为唯一全库结构地图，解释工作流层与内容库层如何对应。
- [[00-管理/知识库工作台]]：降级为后台整理入口，保留治理和维护链接。
- [[00-管理/00-管理索引]]：只保留管理、审查、配置和历史文档入口。
- [[标签仪表盘]]：保留为质量检查入口，不承担导航职责。

## 标签与属性规则

继续使用现有多维标签体系，不新建独立标签宇宙。正式笔记至少保留：

```yaml
---
type: 笔记
domain: 技术
status: 进行中
tags:
  - 领域/技术
  - 类型/笔记
---
```

索引页使用 `type: 索引`，主题地图使用 `type: MOC`，工作台使用 `type: 工作台`，治理页使用 `type: 管理`。状态值收敛到 `进行中`、`待处理`、`已完成`、`归档`、`草稿`、`跟踪中`。历史剪藏中已有的英文或外部状态不强制一次性改写，除非正在编辑该文件。

## 内容整理规则

1. 入口页先收敛，再整理正文。避免在迁移过程中继续扩大入口数量。
2. 编号目录优先保留，不进行无必要大搬迁。
3. 历史整理文档优先归档或降频链接，不直接删除。
4. 空文件、整理过程临时文件、确认无内容价值的占位文件可以删除。
5. 长文剪藏保留原文，补充摘要、个人判断、相关主题和后续动作。
6. 大文件优先处理 `10-技术笔记/sd.md`、Karpathy 剪藏、`40-知识库` 五章资料。
7. 移动或重命名后必须同步修正 Obsidian 双链。

## 实施阶段

### 阶段一：盘点与保护

生成全库清单、入口清单、索引清单、空文件清单、长文清单、疑似断链清单。记录当前脏工作区，只处理本次任务相关文件，不改动 `.obsidian` 插件状态文件。

### 阶段二：入口收敛

重写 `README.md`、[[首页]]、[[HUB/Home]]、[[HUB/Map]]、[[00-管理/知识库工作台]]、[[00-管理/00-管理索引]]，明确各入口唯一职责。

### 阶段三：索引重建

检查每个一级目录的 `00-索引` 或等价入口，统一“用途、核心入口、最近应处理内容、相关地图”的结构。索引只解释文件夹有什么，不替代主题 MOC。

### 阶段四：内容提炼

处理当前最高价值和最高噪声内容：`sd.md`、Karpathy 剪藏、`40-知识库` 方法论文档、AI Topics、思维主题地图。目标是补摘要、个人判断、相关链接和下一步，不追求一次性重写所有正文。

### 阶段五：归档与清理

把历史整理方案、过期占位和低频维护文档统一移入归档入口或保留在历史区并降低曝光。删除空文件和整理临时文件。确认没有新增无效空目录。

### 阶段六：验证

运行空文件扫描、Markdown 清单扫描、frontmatter 分布扫描、双链疑似断链扫描和 git 状态检查。最终输出变更摘要、剩余风险和后续维护建议。

## 验收标准

- [[HUB/Home]] 是明确的日常入口。
- [[HUB/Map]] 能解释工作流层和内容库层的关系。
- `README.md` 和 [[首页]] 不再和主入口重复承担复杂操作面板。
- `00-管理` 不再承担日常导航职责，只保留后台治理。
- 每个主要一级目录都有清楚入口。
- 空文件和整理临时文件已清理。
- 被移动或重命名文件的双链已同步修正。
- 历史文档优先归档或降频，不误删知识内容。
- 输出最终清理记录和剩余待办。

## 非目标

- 不彻底重建所有目录。
- 不批量删除历史知识正文。
- 不为每个小概念提前创建空 MOC。
- 不一次性强制改写所有 frontmatter。
- 不修改 `.obsidian` 插件运行状态，除非用户单独要求。
