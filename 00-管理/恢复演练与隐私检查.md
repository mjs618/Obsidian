# 恢复演练与隐私检查

## 定位

这页用于确认知识库在换设备、误删、插件失效或同步异常时能恢复，也用于检查哪些内容不适合直接提交、同步或发送给外部 AI 工具。

## 每月恢复检查

| 检查项 | 标准 | 入口 |
| --- | --- | --- |
| Git 状态 | 没有意外移动、未跟踪敏感文件或大量运行态变更 | [[00-管理/Git 与 Obsidian 状态文件规则]] |
| 远程备份 | 最近一次重要整理后已经 push 或有异地副本 | [[00-管理/Git 与 Obsidian 状态文件规则#备份策略]] |
| 首页可用 | [[HUB/Home]]、按钮和 Dataview 视图可打开 | [[SYSTEM/必要插件清单]] |
| 核心入口 | [[HUB/Map]]、[[PARA/Projects]]、[[ZETA/Permanent Notes]] 可用 | [[HUB/Map]] |
| 模板可用 | 原生模板和自动化模板路径仍准确 | [[Templates/00-索引]] |

## 每季度恢复演练

| 步骤 | 验收标准 |
| --- | --- |
| 在临时目录克隆或复制一份 vault | Markdown 正文、索引和附件能打开 |
| 恢复必要插件 | 首页、Dataview、Meta Bind、Tasks、Templater、Obsidian Git 可用 |
| 打开主入口 | [[HUB/Home]] 和 [[HUB/Map]] 能解释当前结构 |
| 检查一条项目链路 | 从 [[PARA/Projects]] 能进入项目正文和相关技术笔记 |
| 检查一条知识链路 | 从 [[ZETA/Permanent Notes]] 能进入主题、来源和输出 |

## 隐私与敏感信息检查

| 内容类型 | 风险 | 处理 |
| --- | --- | --- |
| 工作项目细节 | 客户、设备、内部流程或未公开方案 | 提交前确认是否应保留原文 |
| 账号、密钥、路径 | 泄露环境和权限 | 不写入正文；如已写入，单独清理并换密钥 |
| 个人生活记录 | 家庭、健康、财务或身份信息 | 默认不用于公开输出 |
| AI 提示词使用记录 | 可能包含客户资料或未公开任务 | 记录效果时脱敏，必要时只留摘要 |
| 剪藏和转录 | 版权和来源风险 | 保留来源，输出时用摘要和自己的判断 |

## 使用外部 AI 前

- 只发送完成任务所需的最小上下文。
- 删除账号、密钥、客户名、内部路径和未公开材料。
- 长文剪藏先摘要，不直接整篇复制到外部工具。
- 高风险领域先看 [[20-AI/AI提示词库/10-网络精选/11-高风险模板使用边界]]。
- 重要输出交付前看 [[20-AI/AI提示词库/10-网络精选/27-输出验收与交付检查清单]]。

## 处理原则

- 自动提交不等于异地备份。
- 能恢复的系统才算稳定系统。
- 能脱敏的记录不保留原始敏感信息。
- 发现敏感内容时先停下确认，不做批量替换。
