# 知识库优化路线图

## 当前混乱来源

这个库已经有结构，但入口层级偏多：根 README、管理索引、标签仪表盘、分区索引、历史整理文档都在承担“导航”职责。用户实际使用时容易不知道该从哪个页面开始。

另一个问题是内容成熟度混在一起：项目、速查表、剪藏、主题占位、治理文档都已经归档到分区，但还没有稳定区分“收集、整理、沉淀、复用”四种状态。

## 推荐结构

不建议继续大规模移动文件。当前编号结构已经足够稳定，下一步应该做“入口收敛”：

```mermaid
flowchart TD
    Home[HUB Home 日常入口] --> Inbox[HUB Inbox / 未分类]
    Home --> Action[30-工作 项目行动]
    Home --> Knowledge[10/20/40/60 知识沉淀]
    Home --> Resources[70/80 资料来源]
    Home --> System[00-管理 后台治理]
    Home --> Archive[99-归档]

    Knowledge --> MOC[主题 MOC]
    Resources --> Extract[摘要/卡片]
    Extract --> MOC
    Action --> Review[周报/复盘]
    Review --> MOC
```
