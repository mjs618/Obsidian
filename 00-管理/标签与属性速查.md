## type

| type | 用途 |
| --- | --- |
| 索引 | 文件夹入口 |
| MOC | 跨文件夹主题地图 |
| 工作台 | 日常操作入口 |
| 管理 | 规则、清单、配置、审查 |
| 笔记 | 普通知识笔记 |
| 项目 | 工作或个人项目 |
| 资源 | 来源、数据、工具、参考资料 |
| 周报 | 周工作总结 |
| 归档 | 历史参考或不再活跃内容 |
| 审查记录 | 健康检查、结构审查和整理记录 |
| 设计说明 | 方案设计和实施前规格说明 |

| status | 含义 |
| --- | --- |

## 标签原则

- 每篇正式笔记至少一个 `领域/*` 和一个 `类型/*`。
- 状态标签只在需要 Dataview 或任务筛选时使用。
- 不为一次性小概念创建过细标签。
- 能用链接表达关系时，优先用链接，不要堆标签。
- `重要` 用于真正会反复访问或指导行动的笔记。
- 工作流层页面可以使用 `MOC` 或 `工作台`，但正文型知识仍优先使用 `笔记`、`项目`、`资源`。

## 何时建 MOC

满足任一条件再建：

- 一个主题已经有 3 篇以上相关笔记。
- 一个主题跨越多个文件夹。
- 需要为项目、学习或输出建立长期入口。
- 普通索引已经无法解释这个主题的内在关系。
