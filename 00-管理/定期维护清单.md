# 定期维护清单

## 每日 5 分钟

- [ ] 从 [[HUB/Home]] 开始，不从文件夹树随机翻找。
- [ ] 把当天新增内容先放到 [[HUB/Inbox]] 或今日笔记，不现场做复杂分类。
- [ ] 从 [[PARA/Projects]] 选择 1 个项目，只确认一个下一步。
- [ ] 给新正式笔记补一个 `领域/*` 和一个 `类型/*` 标签。
- [ ] 把需要继续处理的事项标成 `状态/待处理` 或任务。
- [ ] 写入当天最重要的一个产出或观察，并链接到项目、主题或资料。

## 每周 20 分钟

- [ ] 检查 [[未分类/00-索引|未分类索引]]，处理临时文件。
- [ ] 检查 `待整理`、`待复习`、`状态/进行中`。
- [ ] 打开 [[HUB/Tasks]]，处理页面级整理队列中的 1-2 项。
- [ ] 从 [[HUB/Inbox]] 中挑 3-5 条内容，分别决定去项目、资料、ZETA、归档或删除。
- [ ] 必要时再打开 [[00-管理/知识库工作台]]，处理后台治理问题。
- [ ] 检查空日记和空模板占位，决定补齐、归档或删除。
- [ ] 为新增的重要笔记补充至少一个反向入口或分区索引链接。
- [ ] 运行一次 Git 状态检查，确认是否有意外移动或未跟踪文件。
- [ ] 手动运行一次 Linter，只处理本周新增或修改过的笔记。

## 每月 45 分钟

- [ ] 复制 [[00-管理/审查记录/知识库健康检查模板|知识库健康检查模板]]，生成当月审查记录。
- [ ] 检查 [[00-管理/审查记录/2026-05-05-元数据补齐清单]]，按批次补齐 3-5 个文件的元数据。
- [ ] 检查 [[00-管理/审查记录/2026-05-10-模块健康检查]]，确认模块边界和元数据例外仍准确。
- [ ] 检查每个分区的 `00-索引.md` 是否仍准确。
- [ ] 检查 [[HUB/Home]] 和 [[HUB/Map]] 是否仍是唯一主入口和结构地图。
- [ ] 检查根目录是否有新的杂项文件；一次性产物按 [[00-管理/Git 与 Obsidian 状态文件规则]] 处理，长期资料进入 `00-管理`、`未分类` 或对应分区。
- [ ] 检查长文剪藏是否需要提炼摘要或主题卡片。
- [ ] 检查 [[HUB/Outputs]] 和 [[HUB/Review]]，确认本月是否有知识转成成果或 Permanent Note。
- [ ] 检查 [[00-管理/恢复演练与隐私检查]]，确认备份、恢复和敏感信息边界。
- [ ] 检查 `99-归档` 是否有可合并或可删除的旧内容。

## 每季度 60 分钟

- [ ] 审查标签体系是否出现同义标签、空标签或过细标签。
- [ ] 审查 `20-AI/AI提示词库` 的资产标签是否仍局限在提示词库内部，没有扩散成全库通用标签。
- [ ] 决定是否推进结构迁移，例如 `20-AI`、模板合并、根目录清理；默认先补规则，不做大规模移动。
- [ ] 检查插件和模板是否匹配当前使用方式，尤其是 [[SYSTEM/必要插件清单]] 中“必要”和“非必要”插件是否仍准确。
- [ ] 确认 Git 远程同步、本地快照和异地备份策略仍有效；30 分钟自动提交不单独视为完整备份。
- [ ] 做一次最小恢复演练，并检查外部 AI 使用前的脱敏规则是否仍足够。
- [ ] 检查 `SYSTEM/TEMPLATE/FORMAT` 中是否存在未被 QuickAdd、Templater 或 Journals 使用的模板。

## 维护原则

- 先保证能找回，再追求结构漂亮。
- 每次只处理一个分区，避免大规模迁移失控。
- 有批量移动或重命名前，先提交当前稳定状态。
- 工作流层只负责进入和流转，长期正文仍回到内容库层。
