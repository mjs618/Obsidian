# Codex 持久记忆库操作说明

## 定位

`E:\Obsidian\Codex` 是 Codex 的持久跨项目记忆库，用来保存围绕用户工作的滚动上下文。它不是聊天记录归档，而是一个可查阅、可编辑、可对比、可复用的 Markdown 记忆系统。

核心原则：线程可以很长，但有价值的记忆必须沉淀为文件。

## 启动规则

开始重要工作会话时，先快速浏览本文件。

如果任务涉及已有人员、项目、决策、待办、重复流程或长期背景，再按需查看：

- `TODO.md`
- `people/`
- `projects/`
- `agent/`
- `agent/open-loops.md`
- `notes/`

## 记录范围

只记录后续有复用价值的持久背景信息：

- 人员：长期偏好、职责、协作方式、关键背景。
- 项目：目标、范围、状态、进展、阻塞、里程碑。
- 决策：会影响后续工作的技术、产品、流程或协作决定。
- 待跟进事项：尚未关闭的问题、确认项、后续动作。
- 重复性工作流：可复用步骤、检查清单、提示词、操作习惯。
- 可复用想法：未来可能用于项目、写作、自动化或决策的想法。

不要记录：

- 完整聊天记录。
- 一次性闲聊或短期上下文。
- 密钥、Token、密码、凭证或敏感隐私信息。
- 没有长期价值、无法复查或无法执行的泛泛总结。

## 写入位置

- `TODO.md`：明确的跨项目待办和已完成事项。
- `people/`：人员相关的长期信息。
- `projects/`：项目状态、进展、决策、阻塞和下一步。
- `agent/`：Codex 工作流、复用提示词、检查清单和操作约定。
- `agent/open-loops.md`：尚未归属具体项目、但需要后续闭环的问题。
- `notes/`：通用背景、每日笔记、可复用想法和暂不归类的信息。

信息应写到最相关的页面。能链接已有笔记时，优先使用 Obsidian wikilink。

## 工作方式

- 对重要工作流，优先维护持续线程和明确目标，而不是每次从零开始。
- 开始任务时，先识别成功标准、可验证结果和需要查看的上下文。
- 执行过程中，接受用户随时补充方向、修正偏好或插入下一步。
- 产出文件、网页、表格、幻灯片或其他 artifact 时，尽量让结果可直接检查和迭代。
- 对长期工作，优先留下可复查的文件变更；让 diff 成为记忆审查界面。

## 更新触发

当出现以下情况时，应更新记忆库中的相关页面：

- 了解到关于人员的持久信息。
- 项目取得进展、状态变化或出现阻塞。
- 做出影响后续工作的决策。
- 新增、关闭或推进了待跟进事项。
- 形成了可复用工作流、提示词、检查清单或操作习惯。

如果不确定某条信息是否值得长期保存，先询问用户。

## 会话收尾

结束重要工作会话前，执行一次记忆收尾：

1. 判断本次会话是否产生值得持久记录的内容。
2. 如有必要，更新对应 Markdown 文件。
3. 将尚未解决的待跟进事项记录到 `TODO.md` 或 `agent/open-loops.md`。
4. 在最终回复中说明修改了哪些记忆文件；如果没有需要记录的内容，也明确说明未更新记忆库。

## 写作约定

- 默认使用中文。
- 保持简洁直接，记录事实、状态、决策和下一步。
- 不直接转储对话。
- 不主动重构、移动或删除既有笔记，除非用户明确要求。
- 不为一次性信息创建页面。
