# Codex 持久记忆库操作说明

## 定位

`E:\Obsidian\Codex` 是 Codex 的持久跨项目记忆库，用来保存可复用的背景、决策、项目状态和工作流。它不是聊天记录归档。

本文件只规定记忆库的读写方式；会话级语言、执行、安全和授权规则见 `agent/codex-personalization.md`。

## 启动时

开始重要工作时，先快速浏览本文件。任务涉及人员、项目、决策、待办、重复流程或长期背景时，再按需读取相关页面：

- `TODO.md`
- `people/`
- `projects/`
- `agent/`
- `agent/open-loops.md`
- `notes/`

重要任务进入执行前，再按相关性完成一次任务前召回：

1. 读取当前项目页，确认目标、状态、已知约束和下一步。
2. 检索相关历史决策、失败案例、检查清单、SOP 或 Skill。
3. 只在实际影响本次方案时说明复用了哪些历史记忆；没有匹配内容时不虚构引用。

## 记录什么

只记录后续有复用价值、可复查、可执行的内容：

- 人员的长期偏好、职责和协作方式
- 项目的目标、范围、状态、进展、阻塞和下一步
- 会影响后续工作的技术、产品或流程决策
- 尚未闭环的确认项和跟进事项
- 可重复使用的工作流、检查清单、提示词和操作习惯
- 未来可能复用的想法

不要记录完整聊天、一次性上下文、泛泛总结、密钥、Token、密码、凭证或其他敏感隐私信息。

## 写到哪里

- `TODO.md`：跨项目待办和已完成事项
- `people/`：人员长期信息
- `projects/`：项目状态、决策、阻塞和下一步
- `agent/`：Codex 工作流、提示词、检查清单和操作约定
- `agent/open-loops.md`：尚未归属具体项目但需要闭环的问题
- `notes/`：通用背景、日常笔记、可复用想法和暂不归类的信息

优先写入最相关的既有页面；能链接已有笔记时使用 Obsidian wikilink。不为一次性信息新建页面。

## 何时更新

出现以下情况时，更新相关页面：

- 形成了可复用的人员、项目、决策或工作流信息
- 项目状态、进展、阻塞或里程碑发生变化
- 新增、关闭或推进了待办/跟进事项

记忆更新应保持小而可审查。若不确定信息是否值得长期保存，先询问用户。

## 结果校正与经验升级

重要任务完成后，判断本次结果对已有记忆的影响：

- 历史判断被证实：补充验证条件和适用边界。
- 历史判断被推翻：保留旧结论，标明失效原因、新证据和当前结论。
- 结果仍不确定：记录待验证条件，不提前升级为长期规则。

经验按真实复用次数逐级升级：

1. 首次出现：写入最相关的项目页。
2. 同类经验第二次出现且仍有效：升级为检查清单或 SOP。
3. 第三次验证有效且适合自动执行：升级为 Skill、模板或固定规则。

经验升级不扩大任务授权范围；删除、外部写入和敏感信息处理仍遵循会话级安全规则。

## 会话收尾

结束重要工作前，检查本次是否产生持久信息：

1. 有必要时更新最相关的 Markdown 页面。
2. 将未解决且值得跟进的事项写入 `TODO.md` 或 `agent/open-loops.md`。
3. 在最终回复中说明改动了哪些记忆文件；没有更新时也明确说明。

不要直接转储对话；只沉淀事实、状态、决策和下一步。

## 写作约定

- 默认使用中文，保持简洁直接。
- 保留既有笔记的语言和语气。
- 不主动移动、删除、重命名或批量重构既有笔记，除非用户明确要求。
