## 定位

这页用于集中记录提示词失败案例。真正能提升提示词库质量的，不是成功样例，而是失败样例：它能暴露目标、上下文、变量、风险和验收标准的缺口。

## 失败类型判定表

| 类型 | 典型表现 | 应回写到哪里 |
| --- | --- | --- |
| 目标失败 | 输出方向偏了，不解决原任务 | Prompt 的任务目标和成功标准。 |
| 上下文失败 | 模型编造背景或误解对象 | 输入变量和资料约束。 |
| 格式失败 | 表格/JSON/章节漂移 | 输出格式和示例。 |
| 证据失败 | 结论无来源或来源不匹配 | 证据表和“资料不足”规则。 |
| 风险失败 | 侵权、专业误导、过度承诺 | warning、风险标签、高风险边界页。 |
| 交付失败 | 结果不可执行或无法验收 | 质量门和验收清单。 |
| 成本失败 | 太长、太慢、输出冗余 | 拆分模板或压缩任务。 |

## 修复优先级

| 优先级 | 标准 | 动作 |
| --- | --- | --- |
| P0 | 产生法律、医疗、财务、版权或事实误导风险 | 立即加 warning，必要时移出推荐入口。 |
| P1 | 影响交付质量或业务判断 | 修改模板并补边界样例。 |
| P2 | 输出格式不稳定 | 增加 schema、示例和自检清单。 |
| P3 | 表达冗长或风格不佳 | 优化文案，不影响主流程。 |

## 复盘提示词

```markdown
你是提示词失败案例分析员。请根据一次失败输出，判断问题出在提示词、输入资料、模型能力还是验收标准。

原提示词：
{{原提示词}}

用户输入：
{{用户输入}}

期望结果：
{{期望结果}}

实际输出：
{{实际输出}}

请输出：
1. 失败类型。
2. 根因判断。
3. 哪些句子导致失败。
4. 应该修改提示词、输入变量、输出格式还是风险边界。
5. 修复后的最小改动。
6. 需要补充的测试样例。
7. 是否需要降级、加 warning 或归档。
```

## 维护规则

1. 重要提示词每出现一次明显失败，都要记录。
2. 同一模板连续 3 次同类失败，必须重构或降级。
3. P0 风险失败必须当天处理。
4. 修复后必须补测试样例，不只改正文。
5. 失败案例进入 [[20-AI/AI提示词库/10-网络精选/10-模板元数据与测试样例集|模板元数据与测试样例集]] 的对应样例区。
