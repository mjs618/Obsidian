# 上下文打包与资料清洗规范

## 定位

很多提示词失败不是因为 Prompt 写得差，而是输入资料混乱。本页用于把资料整理成模型可处理的上下文包，降低编造、遗漏、误解和格式漂移。

## 上下文包结构

```markdown
## 任务目标
{{要得到什么结果}}

## 使用对象
{{谁会看/谁会用}}

## 背景
{{必要背景，不超过 300 字}}

## 原始资料
### 资料 1：{{标题}}
- 来源：
- 日期：
- 可信度：
- 内容摘要：
- 原文摘录：

### 资料 2：{{标题}}
...

## 已知事实
- 

## 待核实信息
- 

## 禁止假设
- 

## 输出要求
- 
```

## 资料清洗规则

| 问题 | 清洗方式 |
| --- | --- |
| 多份资料来源混杂 | 给每份资料编号。 |
| 有事实也有观点 | 拆成“事实/观点/推断/未知”。 |
| 有旧数据 | 标注日期和是否过期。 |
| 有来源不明内容 | 标为“来源不明”，不要当证据。 |
| 有重复段落 | 合并重复，只保留最完整版本。 |
| 有冲突信息 | 保留冲突，不替用户强行判断。 |
| 有敏感信息 | 脱敏或删除不必要字段。 |
| 资料很长 | 分块编号，先摘要再处理。 |

## 资料编号规范

| 编号 | 类型 | 示例 |
| --- | --- | --- |
| `D1` | 文档 | `D1-客户访谈纪要` |
| `W1` | 网页 | `W1-官网产品页` |
| `R1` | 研究报告 | `R1-行业报告摘要` |
| `T1` | 表格 | `T1-销售数据` |
| `I1` | 图片 | `I1-页面截图` |
| `C1` | 代码 | `C1-报错日志` |

## 高价值上下文原则

1. 少给无关背景，多给任务相关事实。
2. 重要约束放前面，不要埋在长文最后。
3. 资料之间必须可引用，例如 `D1`、`W2`。
4. 明确哪些信息不能被模型假设。
5. 输出要求要和资料规模匹配。

## 上下文压缩提示词

```markdown
你是上下文整理员。请把下面资料压缩成可供 AI 稳定处理的上下文包。

任务目标：
{{任务目标}}

原始资料：
{{粘贴资料}}

请输出：
1. 资料编号表。
2. 已知事实。
3. 观点和推断。
4. 待核实信息。
5. 冲突信息。
6. 禁止假设。
7. 推荐给模型的最终上下文包。

要求：
- 不新增资料中没有的信息。
- 来源不清的内容标为“来源不明”。
- 信息不足时写“待补充”。
```

## RAG资料包要求

如果用于 RAG 或知识库问答，每块资料至少包含：

| 字段 | 说明 |
| --- | --- |
| `id` | 唯一编号。 |
| `title` | 资料标题。 |
| `source` | 来源或路径。 |
| `date` | 日期，未知则写 null。 |
| `trust` | 高/中/低。 |
| `content` | 原始内容或片段。 |
| `summary` | 简要摘要。 |
| `limitations` | 局限或使用边界。 |

## 输入前检查

| 检查项 | 通过标准 |
| --- | --- |
| 任务目标 | 一句话能说清。 |
| 资料编号 | 每份资料有编号。 |
| 来源 | 关键事实有来源。 |
| 日期 | 时效性资料有日期。 |
| 冲突 | 冲突信息未被删除。 |
| 敏感信息 | 已脱敏或说明必要性。 |
| 禁止假设 | 明确不能编造的部分。 |
