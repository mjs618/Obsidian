# 平台与模型提示策略

## 核心判断

不同平台的提示策略不应完全一样。真正有用的提示词库，需要记录“在哪个模型/平台上有效”，而不是只保存一段文本。

## 平台策略表

| 平台/来源 | 更适合沉淀什么 | 使用建议 |
| --- | --- | --- |
| OpenAI / Cookbook | 生产级提示词、评估、结构化输出、多模态、代码代理 | 把提示词和 eval 样例绑定，记录失败案例。 |
| Claude / Anthropic | 长上下文、文档分析、写作、企业流程、严谨指令 | 把上下文、角色、输出约束写清楚，避免只给短命令。 |
| Gemini / Vertex AI | 多模态、分类、抽取、企业数据场景 | 善用图片、视频、表格等输入，明确输出 schema。 |
| GitHub Copilot | 代码解释、生成测试、局部重构、IDE 上下文 | 先给目标，再指明相关文件、函数、约束和测试。 |
| Microsoft 365 Copilot | 邮件、会议、文档、团队办公 | 强调受众、语气、材料来源和交付格式。 |
| Fabric Patterns | 总结、提取、分析、重写等工作流 | 适合改写成“输入 -> 处理 -> 输出”的任务模板。 |
| LangSmith Prompt Hub | 提示词模板管理和变量化 | 公共 Prompt Hub 是用户生成内容，适合参考，不直接信任。 |

## 模型切换检查清单

详细迁移流程见 [[20-AI/AI提示词库/10-网络精选/25-模型适配与迁移指南|模型适配与迁移指南]]。

当一个提示词从 A 模型迁移到 B 模型时，至少检查：

1. 输出格式是否仍稳定。
2. 是否需要减少或增加步骤。
3. 是否依赖某个平台的工具语法。
4. 是否需要把隐含上下文显式写出。
5. 是否有 3-5 个测试样例验证效果。

## 代码类提示策略

```markdown
你是代码协作助手。请基于以下上下文完成任务。

目标：
{{要做什么}}

项目上下文：
{{框架、语言、目录、约束}}

相关代码：
{{文件路径或代码片段}}

要求：
1. 先说明你对现有代码的理解。
2. 只修改和任务直接相关的部分。
3. 保持现有风格和测试习惯。
4. 给出需要运行的验证命令。

输出：
- 实现思路
- 修改点
- 测试建议
- 风险
```

## 办公类提示策略

```markdown
请基于以下材料生成{{交付物类型}}。

材料：
{{邮件/会议纪要/文档/数据}}

受众：
{{老板/客户/团队/外部合作方}}

目的：
{{汇报/推进/决策/同步/复盘}}

语气：
{{正式/简洁/友好/强执行}}

请输出：
- 标题
- 正文
- 关键信息
- 待办事项
- 需要对方确认的问题
```
