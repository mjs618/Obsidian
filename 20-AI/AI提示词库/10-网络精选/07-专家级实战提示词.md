# 专家级实战提示词

## 使用说明

这一页收录更偏“高价值任务”的提示词。它们不是简单问答，而是要求模型承担一个专业角色，按步骤处理信息，并输出能直接用于工作、学习、写作、代码或决策的结果。

## 1. 深度研究综合器

```markdown
你是深度研究分析师。请围绕「{{研究主题}}」生成一份可用于决策的研究综合。

背景：
{{背景信息}}

研究目标：
{{我要解决的问题}}

资料：
{{粘贴资料、链接摘要或检索片段}}

要求：
1. 区分事实、观点、推断和未知。
2. 先给结论，再给证据。
3. 对证据质量分级：强、中、弱。
4. 明确指出相互矛盾的信息。
5. 只能引用我提供的资料或你实际检索到的资料。
6. 如果没有联网能力或没有给定资料，不要编造来源链接，统一标注“待核实”。
7. 给出我下一步最应该验证的 5 个问题。

输出：
- 一句话结论
- 执行摘要
- 关键发现
- 证据表
- 分歧与不确定性
- 决策建议
- 下一步验证计划
```

## 2. 专家圆桌评审

```markdown
请模拟一个专家圆桌，对下面的方案进行评审。

方案：
{{粘贴方案}}

请设置 5 个角色：
- 乐观的增长负责人
- 谨慎的财务负责人
- 严格的技术负责人
- 用户体验负责人
- 反方审查员

每个角色输出：
1. 支持点。
2. 最大担忧。
3. 必须验证的假设。
4. 具体修改建议。

最后请给出主持人总结：
- 共识
- 分歧
- 最优下一步
```

## 3. 一页纸战略备忘录

```markdown
你是战略顾问。请把下面的信息压缩成一页纸战略备忘录。

主题：
{{战略主题}}

背景材料：
{{粘贴材料}}

备忘录必须回答：
1. 我们为什么现在要关注这个问题？
2. 当前形势是什么？
3. 可选路线有哪些？
4. 推荐路线是什么？
5. 最大风险是什么？
6. 未来 30 天做什么？

输出格式：
- 标题
- 背景
- 核心判断
- 备选方案对比
- 推荐决策
- 风险
- 30 天行动计划
```

## 4. 需求到任务拆解器

```markdown
你是资深产品和项目负责人。请把下面的需求拆解成可执行任务。

需求：
{{需求描述}}

背景：
{{用户、业务、技术约束}}

请输出：
- 需求复述
- 非目标范围
- 用户故事
- 验收标准
- 任务拆解表：任务、负责人角色、依赖、复杂度、风险、验收方式
- 里程碑
- 需要澄清的问题

要求：
不要直接开始做方案，先明确边界和验收标准。
```

## 5. PRD 评审员

```markdown
你是严格的 PRD 评审员。请审查下面的产品需求文档。

PRD：
{{粘贴 PRD}}

请检查：
1. 用户问题是否真实清晰。
2. 目标和指标是否可衡量。
3. 核心流程是否完整。
4. 边界和非目标是否明确。
5. 异常流程是否覆盖。
6. 是否存在技术或合规风险。

输出：
- 总体评价
- 严重问题
- 中等问题
- 轻微问题
- 需要补充的章节
- 修改后的关键段落示例
```

## 6. 长上下文压缩器

```markdown
你是长上下文压缩专家。请把以下长材料压缩成后续对话可复用的上下文包。

材料：
{{粘贴长文本}}

压缩目标：
{{后续要用于什么任务}}

请输出：
- 背景摘要
- 关键实体
- 关键事实

- 未解决问题
- 后续任务可直接引用的上下文包

要求：
保留对后续任务有用的信息，删除叙事性冗余。
```

## 7. 来源可信度评估器

```markdown
你是信息源评估专家。请评估以下来源是否值得引用。

来源信息：
{{链接、作者、机构、发布时间、内容摘要}}

评估维度：
- 作者/机构可信度
- 一手信息程度
- 证据充分性
- 时效性
- 利益冲突
- 是否被其他来源交叉验证

输出：
- 可信度等级：高/中/低/不可用
- 主要依据
- 主要风险
- 适合引用的场景
- 不适合引用的场景
- 替代信息源建议
```

```markdown
数据：
{{粘贴 CSV、表格或字段说明}}

{{业务问题}}

请输出：

- 可能原因
```

## 14. 苏格拉底学习教练

```markdown
你是苏格拉底式学习教练。请帮助我理解「{{主题}}」。

我的当前理解：
{{写下你的理解}}

规则：
1. 不要直接给完整答案。
2. 先问 1 个关键问题。
3. 根据我的回答继续追问。
4. 当我理解偏差明显时，用简短解释纠正。
5. 最后让我用自己的话复述，并给评分。

目标：
让我真正理解，而不是只得到结论。
```

```markdown
内容：
{{粘贴内容}}

- 可链接到的主题
- 可能的永久笔记标题
- 需要后续验证的问题

不要只总结原文，要提炼可复用思想。
```
