# 输出验收与交付检查清单

## 定位

这页用于判断模型输出能不能交付。它不评估提示词本身，而是评估“这一次输出”是否准确、完整、可执行、可复核。

## 交付结论分级

| 结论 | 标准 | 动作 |
| --- | --- | --- |
| 可以交付 | 内容准确、结构完整、风险可控、格式可用 | 交付并记录有效做法。 |
| 修改后交付 | 主体可用，但有局部事实、格式或表达问题 | 修改后再检查。 |
| 不可交付 | 有编造、关键遗漏、专业误导或无法执行 | 回到提示词或资料阶段重做。 |

## 通用验收表

| 维度 | 检查问题 | 不通过表现 |
| --- | --- | --- |
| 目标 | 是否回答了原任务？ | 输出偏题、只泛泛解释。 |
| 事实 | 事实是否来自资料或可靠来源？ | 编造数据、链接、案例。 |
| 完整性 | 是否覆盖关键要求？ | 漏掉限制、字段、步骤。 |
| 结构 | 是否符合指定格式？ | 表格/JSON/章节漂移。 |
| 可执行性 | 下一步是否清楚？ | 建议抽象、不能落地。 |
| 风险 | 是否标注不确定和人工复核点？ | 高风险结论无边界。 |
| 语言 | 是否符合受众和场景？ | 太口号化、太随意或太复杂。 |
| 成本 | 是否过长或冗余？ | 重复解释，难以使用。 |

## 交付前自检提示词

```markdown
你是交付质量审查员。请判断下面这份模型输出是否可以交付。

原任务：
{{原任务}}

输入资料摘要：
{{资料摘要}}

模型输出：
{{模型输出}}

交付对象：
{{谁会使用}}

交付标准：
{{标准}}

请输出：
1. 交付结论：可以交付 / 修改后交付 / 不可交付。
2. 最严重的 5 个问题。
3. 逐项验收表：目标、事实、完整性、结构、可执行性、风险、语言、成本。
4. 需要人工复核的部分。
5. 最小修改方案。
6. 是否需要回到提示词、资料清洗或模型迁移阶段。
```

## 高风险输出验收

法律、医疗、财务、投资、版权、事实研究类输出，必须额外检查：

| 检查项 | 标准 |
| --- | --- |
| 是否声明边界 | 明确不是专业结论或最终建议。 |
| 是否保留不确定性 | 写出资料不足和待核实。 |
| 是否建议人工复核 | 指向律师、医生、财务顾问或负责人。 |
| 是否避免承诺 | 不承诺收益、疗效、胜诉、排名、爆款。 |
| 是否有证据 | 关键结论有资料编号或来源。 |

## 输出类型专项检查

| 输出类型 | 重点检查 |
| --- | --- |
| JSON/表格 | 字段完整、类型正确、缺失值处理一致。 |
| 研究报告 | 证据表、来源质量、不确定性、反方观点。 |
| 文章内容 | 事实不变、标题不过度、结构清楚、版权边界。 |
| PPT/网页 | 信息层级、文字溢出、图片遗漏、移动端可读。 |
| 代码方案 | 符合项目约束、可验证、有测试建议。 |
| 决策建议 | 假设、风险、备选方案、下一步明确。 |
| 知识库笔记 | 原子化、可链接、有适用场景。 |
