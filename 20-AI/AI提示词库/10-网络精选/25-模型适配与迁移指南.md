# 模型适配与迁移指南

## 定位

同一条提示词在不同模型、不同工具、不同上下文长度下，表现可能不同。本页用于把提示词从一个模型迁移到另一个模型时，检查是否需要改结构、改变量、改输出格式或改验证方式。

## 先判断任务类型

| 任务类型 | 迁移重点 | 常见风险 |
| --- | --- | --- |
| 结构化抽取 | 输出 schema、缺失值规则、字段类型 | JSON 漂移、字段编造 |
| 长文分析 | 资料分块、引用位置、摘要层级 | 丢失细节、混淆来源 |
| 写作润色 | 受众、语气、禁用风格、事实不改 | 改变原意、过度发挥 |
| 研究综合 | 证据表、来源分级、不确定性 | 假引用、过度结论 |
| 代码协作 | 文件路径、约束、验证命令 | 忽略项目风格、未验证 |
| 多模态分析 | 事实观察与推断分离 | 把推断当事实 |
| Agent任务 | 成功标准、工具限制、停止条件 | 无限执行、越权改动 |

## 迁移检查清单

| 检查项 | 问题 | 修改建议 |
| --- | --- | --- |
| 上下文长度 | 目标模型是否能稳定处理完整资料？ | 超长资料先用 [[20-AI/AI提示词库/10-网络精选/26-上下文打包与资料清洗规范|上下文打包与资料清洗规范]]。 |
| 输出格式 | 是否要求严格 JSON、表格或代码？ | 增加 schema、示例和“只输出”规则。 |
| 工具能力 | 是否依赖联网、代码执行、文件读取、图片理解？ | 明确工具可用性；无工具时标记待核实。 |
| 推理深度 | 是否需要多步权衡、反例和验证？ | 增加分阶段输出和质量门。 |
| 事实来源 | 是否要求引用来源？ | 只引用给定资料或实际检索资料。 |
| 安全边界 | 是否涉及法律、医疗、财务、版权？ | 接入 [[20-AI/AI提示词库/10-网络精选/11-高风险模板使用边界|高风险模板使用边界]]。 |
| 成本效率 | 提示词是否过长、重复、含大量背景？ | 拆成短版/标准版/完整版。 |

## 通用迁移步骤

1. 先保留原提示词，不直接覆盖。
2. 用 3 个测试样例跑目标模型：常规、边界、异常。
3. 对比输出：格式、事实、完整性、风险边界。
4. 只修改导致失败的部分。
5. 在提示词卡片中记录适用模型、测试日期和失败样例。
6. 如果目标模型表现不稳定，降级为 testing，不进入主用入口。

## 入库规则

1. 没有测试样例的迁移，不算完成。
2. 高风险模板迁移后必须重新审查风险边界。
3. JSON/代码/表格类模板必须验证格式稳定性。
4. 模型专用规则不要写进通用版，避免污染其它场景。
5. 迁移失败样例写入 [[20-AI/AI提示词库/10-网络精选/23-失败案例库与修复记录|失败案例库与修复记录]]。
