# AI日记 - 2026-06-03

## 今日重点

### 1. [[OpenAI]] 把青少年 AI 安全推进到 G7 级别议程
- 类别：政策 / 安全 / 教育
- 时间：2026-06-02
- 摘要：OpenAI 发布面向 G7 的 youth AI safety 倡议，呼吁建立具备国际协作属性的青少年 AI 安全研究与指导机制，并明确提出年龄识别、年度风险评估和默认保护措施等原则。
- 影响：这说明头部模型公司的治理竞争，正在从模型安全与内容治理外溢到年龄分层、教育场景和跨国标准协调。[[政策监管]] 接下来不只看政府立法，也要看公司是否主动把高敏感用户群体治理写成可审查框架。
- 相关：[[OpenAI]] / [[政策监管]]

### 2. [[Anthropic]] 扩大 Project Glasswing，把前沿网络安全能力继续限向关键机构开放
- 类别：安全 / 网络防御 / 模型部署
- 时间：2026-06-02
- 摘要：Anthropic 宣布把 Project Glasswing 从约 50 家初始合作方扩展到约 150 家新机构，覆盖电力、水务、医疗、通信、硬件等关键基础设施与关键开源维护方。
- 影响：这进一步说明前沿模型在网络安全上的真实瓶颈已经从“能不能发现漏洞”转向“能不能组织化地验证、披露、修补并控制滥用风险”。[[Anthropic]] 的竞争点因此越来越像安全运营体系，而不只是模型能力展示。
- 相关：[[Anthropic]] / [[政策监管]]

### 3. [[OpenAI]] 上 AWS 的意义，开始从“模型可用”转向“默认企业入口”
- 类别：产品 / 云分发 / 企业交付
- 时间：2026-06-01
- 摘要：OpenAI 宣布前沿模型与 Codex 已正式在 AWS 上可用，支持客户沿现有安全、采购、计费、治理和部署流程直接采用。
- 影响：虽然这条消息是 6 月 1 日发布，但放到今天看仍然是最重要的企业分发信号之一。AI 平台竞争越来越像“谁先进入企业默认控制平面”，而不是单独比较 API 能力。[[算力基础设施]] 的竞争边界因此继续向云控制面延展。
- 相关：[[OpenAI]] / [[算力基础设施]]

### 4. [[开源模型]] 继续向 physical AI 深水区推进
- 类别：开源 / 自动驾驶 / 世界模型
- 时间：2026-06-01
- 摘要：NVIDIA 发布开放的 Alpamayo 2 Super，同时推出 AlpaGym、OmniDreams 和配套 physical AI agent skills，把开放 VLA、闭环训练和仿真生成整合成更完整的自动驾驶开发栈。
- 影响：开源模型竞争正在继续从语言能力和通用助手外溢到自动驾驶、world model 和 simulation-first 物理 AI 开发体系。值得注意的不是单个模型参数，而是 NVIDIA 正把“开放模型 + 训练框架 + 合成场景 + 工具技能”打包成基础设施层。
- 相关：[[开源模型]] / [[算力基础设施]]

### 5. [[政策监管]] 进入“规则执行 + 专家支撑”并行期
- 类别：监管 / AI Act / 执行

- 影响：监管焦点已经不只是规则文本，而是进入执行支撑、评估方法与监督机制的组织化建设阶段。对头部模型公司和部署方来说，后续压力会更具体地落到分类、证据链和审查协同上。
- 相关：[[政策监管]]

## 趋势点评

今天最值得记录的变化是，AI 行业正在把“能力强”进一步转译成“谁能承担默认责任”。OpenAI 一边进入 AWS 这种企业默认控制平面，一边又把青少年 AI 安全主动推向 G7 议程；Anthropic 则继续把高风险网络安全能力限制在关键机构与受控流程里。头部公司竞争的重点，已经不只是能力是否领先，而是谁更像未来的默认制度节点。

另一条主线是，开放路线正在继续向 physical AI 下沉。NVIDIA 的 Alpamayo 2 Super 并不是孤立模型发布，而是把开放 VLA、闭环 RL、世界模型和 agent skills 一起打包。这意味着 [[开源模型]] 与 [[算力基础设施]] 的边界正在进一步重合，后续比较维度会越来越偏向整栈开发效率与部署闭环。

监管层面，欧盟 AI Act 的执行支持机构就位，也和 OpenAI 对 youth safety 的国际倡议形成呼应：2026 年的治理竞争，正在从原则争论转向具体人群、具体流程和具体执行机制。
