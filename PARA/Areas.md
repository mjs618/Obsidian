## 领域维护规则

- 领域页不追踪细碎任务，任务进入 [[HUB/Tasks]] 或对应项目。
- 每个领域至少保留一个索引入口和一个主题地图或核心清单。
- 领域中的高价值资料应逐步进入 [[ZETA/Permanent Notes]]。

## 领域健康标准

| 标准 | 判断 |
| --- | --- |
| 有入口 | 能从本页进入对应领域索引 |
| 有边界 | 知道什么内容属于这个领域，什么不属于 |
| 有维护动作 | 每月至少能说出一个需要更新、复盘或清理的点 |
| 有输出方向 | 能沉淀为主题地图、原则卡片、项目复盘或长期清单 |

## 领域与项目区别

| 问题 | 放入 |
| --- | --- |
| 是否有明确交付物、截止或下一步 | [[PARA/Projects]] |
| 是否只是长期保持、学习、维护或观察 | [[PARA/Areas]] |
| 是否只是一篇资料或一次输入 | [[PARA/Resources]] |

当领域连续两周出现同一个具体推进动作，就应该拆成项目；当项目结束但仍需要长期维护，就回收到领域。

## 每月维护动作

- 删除已经转为项目的临时内容，避免领域页变成任务堆。
- 检查每个领域是否有一个当前最重要的问题。
- 把重复出现的经验整理为 [[ZETA/Permanent Notes]]。
